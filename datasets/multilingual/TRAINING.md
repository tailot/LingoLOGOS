# Training guide

Three independent runs are available in this folder. All of them read only this folder and
write only inside `datasets/multilingual/checkpoints/`; nothing in the LingoLOGOS source tree is modified,
and **nothing here downloads a model, a vocabulary or a weight file from anywhere**. The
assistant this corpus is meant to train is built from scratch; the parts that exist, the parts
that are still missing and the measurements behind both are in `doc/PURE_MODEL_ROADMAP.md` at
the repository root. The commands below are written from the repository root, but every tool
resolves the corpus and the engine by walking up from its own file in `tools/corpus_paths.py`, so
they also work from any other directory and after a move of this folder.

## 0. Environment

The packages already installed for the engine cover everything in this folder: `torch`, `z3-solver`,
`lark`, `pyyaml`, `numpy`, `pytest`, plus `safetensors`, the release format of the trained weights. Only
the upload step of section 9 needs one more package, `huggingface_hub` (`pip install -e ".[publish]"`),
and the tool imports it inside that step, so building and checking a release folder stays local and
offline.

```powershell
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

The second value should be `True` if you want the neural runs to use the GPU. Grammar
induction, tokenizer learning and mask verification also work on the CPU.

## 1. Consistency check (always run this first)

```powershell
python datasets/multilingual/tools/validate_dataset.py
```

The script re-derives every bracket word, every pattern and every SMT text from the
stored logic trees, checks the parallel groups, the split boundaries, the corpus files,
the chat pairs and the configurations, then builds all 2,698 logical forms in Z3.
It prints `VERDICT: PASS` when everything is consistent. Use `--no-z3` to skip the SMT
part.

## 2. Grammar induction on the bracket algebra

The dataset writes every meaning as a balanced word over `( ) [ ]`, which is the
representation the LingoLOGOS engine induces. This entry point reuses that engine from
the parent repository without changing it.

```powershell
python datasets/multilingual/tools/train_grammar.py --epochs 90 --synthetic 900
```

What happens: the 29 structural words of `corpus/dyck2_train.txt` seed the corpus, and
synthetic Dyck-2 words (depth 5, length up to 28) give the probabilistic grammar enough
statistical variety. Temperature anneals from 1.0 to 0.5, the grammar is extracted with
pruning at 0.01 and exported.

Artifacts in `datasets/multilingual/checkpoints/grammar/`: `grammar_weights.pt`, `grammar.json`,
`grammar.yaml`, `DatasetGrammar.gf`, `metrics.json`.

Expected acceptance gates, all four true:

| Gate | Meaning |
| --- | --- |
| G1 | the exported grammar compiles and every non-terminal has total mass 1 |
| G2 | 100% of the dataset bracket words are generated by the grammar |
| G3 | 100% of the 29 ill-bracketed controls are rejected |
| G4 | Z3 proves `L(G) subset of Dyck-2` with an **UNSAT** verdict |

The run finishes with `FINAL VERDICT: PASS`. `--lenient` keeps exit code 0 on failures,
`--list-only` prints the metrics without writing files.

One honest caveat, measured and repeated here because it is easy to miss: the default
`--init prior` seeds the grammar with the gold Dyck-2 structure (`reference.apply_gold_prior`).
With `--init random` the induction is not solved at this budget: gold rule `F1` is about 0.42
and the extracted grammar over-generates `(]`, which gate G4 then refuses.

## 3. Phase 1: learning the vocabulary of the pure model

```powershell
python datasets/multilingual/tools/train_tokenizer.py --vocab-size 6000
```

The script learns a byte-pair vocabulary from the `train` split of `sft/` only and measures
itself on `train`, `valid` and `test`. It uses no pretrained tokenizer and no external
corpus: the protected alphabet (the four brackets, the 53 operator names, the leaf tags) is
derived from `templates/operators.json`, and merges are learned only inside ordinary words,
never across a formal symbol. Artifacts: `datasets/multilingual/checkpoints/tokenizer/tokenizer.json` and
`metrics.json`.

Measured on the shipped corpus:

| quantity | value |
| --- | --- |
| training texts / pre-tokenized units | 72,840 / 5,214,389 |
| word types | 1,578 |
| atomic units / atomic types | 3,040,076 / 268 |
| learned merges | 3,578, stop reason `no mergeable pair left` |
| vocabulary size | 3,921 (`saturated_at: 3921`) |
| round trip failures | 0 on every split |
| unknown tokens | 0 over 5,786,067 produced tokens |
| formal symbols encoded as one token | 267 of 267 |
| bracket words re-encoded exactly | 13,490 checked, 0 broken |

Gates:

| Gate | Meaning |
| --- | --- |
| T1 | pre-tokenization is reversible, the text is rebuilt from its pieces |
| T2 | no unknown token on any split |
| T3 | every formal symbol of the algebra is a single atomic token |
| T4 | the formal symbols of the held-out splits are already in the vocabulary |
| T5 | every bracket word survives encode plus decode unchanged |

The vocabulary **saturates**: with 1,578 word types and 3,040,076 atomic units there is simply
nothing left to merge past 3,921 entries, so a target of 8,000 to 32,000 pieces is not
reachable on this corpus and `V = 3,921` is the number to size the embedding on. Use
`--limit` for a fast probe, `--all-splits` to train on all three (only for experiments, it
destroys the held-out property) and `--lenient` to keep exit code 0 when a gate fails.

## 4. Phase 2: verifying the symbolic decoding mask

```powershell
python datasets/multilingual/tools/verify_masking.py --samples 300 --refine
```

The mask is a stack automaton over the *symbol* alphabet, built from the arities in
`templates/operators.json` and the leaf shapes observed in the training split; it admits
exactly the legal bracket algebra and nothing else, so an illegal answer is not scored
badly, it is unreachable. The tool checks it against an independent oracle that reuses
`logic_map.is_well_bracketed`, the registry arities and an independent reader, never the
mask itself. Artifact: `datasets/multilingual/checkpoints/masking/masking_metrics.json`.

Measured:

| Gate | Measured |
| --- | --- |
| M1 | 1,350 of 1,350 held-out algebra streams accepted |
| M2 | 16,350 of 16,350 mutated streams refused (crossed bracket, deleted bracket, inserted bracket, truncation, unknown operator, wrong arity, oversized leaf) |
| M3 | 300 of 300 constrained samples are legal trees and well-bracketed words |
| M4 | 52 observed operator and arity pairs agree with the registry, 0 serialization mismatch |
| M5 | 67,190 of 67,190 gold token decisions accepted; closing marker forced at completeness 1,350 times, offered out of place 0 times |

Alphabet of the mask: 53 operators, 136 leaf tags, 75 payload tokens, leaf length profile
`{1: 135, 2: 1}`, 268 vocabulary tokens for the masked alphabet. With `--refine` the extra
restriction "which child kind sits at which position" is learned from the training split only
(83 refined pairs) and the held-out split is still accepted 1,350 of 1,350.

Two honest caveats recorded in the metrics file: the `unknown_leaf` controls were all
discarded because every held-out leaf symbol is already inside the training alphabet, and one
of the 53 registered operators never occurs in the corpus, so its arity is never exercised.
`--samples`, `--max-depth`, `--max-symbols`, `--seed`, `--list-only` and `--lenient` control
the run.

## 5. Phase 3: the network

The network lives in `src/neuro_symbolic/model.py` and the training machinery in
`src/neuro_symbolic/training.py`; both are pure PyTorch, with no pretrained weight, no hub download and
no third-party tokenizer. The checkpoint metadata states `"external_weights": "none"`, and `load_model`
refuses an archive whose format name is not `lingologos-transformer-1`.

| item | value |
| --- | --- |
| blocks | 6 encoder plus 6 decoder, pre-norm, 8 heads of 64 |
| width | `d_model` 512, `d_ff` 2048, dropout 0.1 |
| positions | learned absolute, budget 96 per side (measured need: 68 encoder, 92 decoder protocol tokens) |
| parameters | 48,253,952 trainable: encoder blocks 18,914,304, decoder blocks 25,224,192, token tables 4,015,104, position tables 98,304, final norms 2,048 |
| initialization | LayerNorm gains 1 / biases 0, embeddings and positions N(0, 0.02), Kaiming on the ReLU side of each feed-forward block, Xavier elsewhere, uniform biases, decoder input tied to the output projection |

`python -m pytest -v tests/test_model.py` runs the 20 checks that pin this down (config guards,
causality, additive mask shapes, invariance to encoder padding, zero `<PAD>` row, weight tying, seed
determinism of the initialization, the He versus Xavier bound, save and load round trip).

## 6. Phase 4: training the pure model

```powershell
python datasets/multilingual/tools/train_model.py --epochs 20 --batch-size 64 --lr 5e-4 --warmup-steps 0 --amp auto
```

The loop trains on the 12,140 pairs of the training split only, with cross-entropy computed over the
admissible tokens of each position: the admissible sets are interned into a table (13 distinct rows over
the whole corpus, widest 136 tokens, narrowest 1), materialized once as a dense boolean matrix on the
device and gathered per batch, so masking costs one `masked_fill_` instead of one automaton call per
token. AdamW with beta 0.9 and 0.98, epsilon 1e-9, weight decay 0.01 on weight matrices only, gradient
clipping at 1.0, warmup of one epoch (190 steps at batch 64, since 4,000 steps of warmup would be 21
epochs here) and cosine decay to 10 percent of the peak rate.

Measured, 20 epochs, seed 17, bf16, 809 seconds on the RTX 5070 Ti:

| quantity | epoch 1 | epoch 20 |
| --- | --- | --- |
| masked cross-entropy (train) | 0.3666 | 0.000246 |
| perplexity over admissible alternatives | 1.44 | 1.00025 |
| free-position accuracy | 0.555 | 0.99931 |
| exact target sequence, teacher forced | 0.021 | 0.99333 |
| validation loss | 0.1112 | 0.00558, best 0.00404 at epoch 11 |
| greedy constrained decoding, 16 validation sentences | 0.125 | 0.9375 |
| throughput and peak memory | -- | 340.6 samples/s, 2,467,995,648 bytes |

Only 19.66 percent of supervised positions are real choices: the automaton forces the other 80 percent
to a single token (the space between symbols, the closing marker, `<EOS>`, the leaf payload
continuation), so the free-position figure is measured over the hard fifth of the sequence. Artifacts
land in `datasets/multilingual/checkpoints/model/`: `model.pt`, `model_best.pt`, `model_config.json`, `history.json`
and `train_metrics.json`. Useful flags: `--limit`, `--device cpu`, `--amp off`, `--epochs`,
`--warmup-steps`, `--eval-every`, `--generation-samples`, `--out-dir`, `--dry-run`.

## 7. Phase 5: held-out gates and the Z3 audit

```powershell
python datasets/multilingual/tools/evaluate_model.py --checkpoint datasets/multilingual/checkpoints/model/model_best.pt --split test --min-exact-tree-accuracy 0.90
```

The tool decodes the whole split under the mask, then reports four gates and writes a JSON report with
the per-gate `passed` flags and a `final_verdict` (exit code 1 on failure, so it can gate a pipeline):

| gate | `model_best.pt` (epoch 11) | `model.pt` (epoch 20) |
| --- | --- | --- |
| E1 exact tree on 675 test rows | 0.9393 | **0.9511** |
| E1 bracket skeleton, truncations | 1.0000, 0 | 1.0000, 0 |
| E2 streams accepted by the independent oracle | 675 / 675 | 675 / 675 |
| E3 rebuilt in Z3: contingent, unsatisfiable, valid, build errors | 675, 0, 0, 0 | 675, 0, 0, 0 |
| E3 numbers absent from the input sentence | 5 (0.0074) | 7 (0.0104) |
| E5 legality with mask versus without | 1.0000 versus 0.0000 | 1.0000 versus 0.0000 |

The mistakes are labelling mistakes, not structural ones: the bracket skeleton is always right, and the
error concentrates in the `threshold` logic family (0.845 over 200 rows) and in the `domotica` and
`salute` domains, while `recurrence`, `frequency` and `agenda` are perfect. Language is not the problem
(0.941 to 0.956 across the five). Without the mask, at identical weights, no stream reaches the closing
marker and the decoder repeats symbols until the step budget expires; its raw argmax is outside the
admissible set at 83.6 percent of the teacher-forced positions. That is the measurement of what the
symbolic constraint contributes. Reports: `datasets/multilingual/checkpoints/evaluation/<checkpoint>-<split>.json`.
Flags: `--split`, `--limit`, `--batch-size`, `--sampling --temperature`, `--no-z3`, `--no-ablation`,
`--no-refine`, `--min-exact-tree-accuracy`, `--max-invented-number-rate`, `--max-noncontingent-rate`,
`--out`. Gate E4 (verbalization, tree back to sentence) is not trained and therefore not reported.

## 8. Regenerating or extending the dataset

The items are produced from the 50 templates and the multilingual lexicon:

```powershell
python datasets/multilingual/tools/generate_dataset.py --combos-per-template 60 --seed 13
python datasets/multilingual/tools/validate_dataset.py
```

Adding a sentence pattern means adding one entry to the relevant file in
`datasets/multilingual/templates/`; the validator then checks that the new patterns are covered by
the lexicon, that the bracket words stay balanced and that the SMT translation builds.
After a regeneration, rerun the tokenizer and the mask gates: both learn their alphabet
and their leaf shapes from the corpus, so a new domain has to relearn them.

## 9. The pipeline in GitHub Actions

The folder has its own pipeline, `.github/workflows/dataset.yml`, kept separate
from the CI of the engine. It runs on every push that touches `datasets/multilingual/**` and it
can be started by hand from the Actions tab with the "Run workflow" button.

Stages:

1. `consistency`: the validator, then the tokenizer gates `T1` to `T5`, then the mask
   gates `M1` to `M5`; the vocabulary and both metric files are uploaded as artifacts.
2. `grammar`: induction on the bracket algebra, 90 epochs, artifacts uploaded.
3. `release`: the corpus, the induced grammar and the learned vocabulary are packaged and
   published in a GitHub Release of this repository.

To publish the file at the end, either start the workflow with the release option
checked, which creates the tag `dataset-v<run number>` by itself, or push a tag:

```powershell
git tag dataset-v2
git push origin dataset-v2
```

The release contains `lingologos-dataset.zip` (items, chat pairs, corpus,
templates, configurations, tools and the two documents), `grammar.json`,
`grammar.yaml`, `DatasetGrammar.gf` and `grammar-metrics.json` (the grammar the
pipeline induced, with gates G1 to G4), `tokenizer.json` and `tokenizer-metrics.json`
(the vocabulary learned from the corpus, with gates T1 to T5), `masking-metrics.json`
(the symbolic decoding gates M1 to M5) and `dataset-stats.json`.

Model weights are deliberately not part of that pipeline. Hosted runners have no GPU and a six-hour
limit, the training of section 6 is an 809-second GPU job on this machine, and `upload-artifact` caps an
artifact near 500 MB with a 90-day expiry while a release asset allows 2 GiB per file. The checkpoint is
built locally, and releasing it is a separate, deliberate act: no stage of the pipeline contacts a hub.

The weights are published on the Hugging Face Hub as `tailot/lingologos-pure-1`, in safetensors form, by
one tool that reads what the training run left on disk:

```powershell
python datasets/multilingual/tools/publish_to_hub.py --checkpoint datasets/multilingual/checkpoints/model/model_best.pt --report datasets/multilingual/checkpoints/evaluation/model_best-test.json --out-dir datasets/multilingual/checkpoints/hub --repo tailot/lingologos-pure-1
```

That command only builds the folder. Adding `--upload`, after putting the access token in `$env:HF_TOKEN`,
pushes it to the hub; without the flag the tool touches no network at all. The folder holds seven files:
`model.safetensors` (193,044,672 bytes, 48,253,952 parameters, the tied output projection stored once and
re-bound on load), `config.json`, `tokenizer.json`, `mask_spec.json`, `evaluation_report.json`,
`metadata.json` and a generated `README.md` card. The mask specification matters: it is the same algebra
mask the trainer used, so a user can keep the hard constraint after downloading the weights instead of
trusting the card. The build refuses a report whose final verdict is not `PASS`, refuses a checkpoint whose
recorded vocabulary disagrees with the tokenizer it names, and loads the written file back to compare its
logits with the checkpoint it came from. For the published weights that round trip covers 261 tensor names
and 50,261,504 parameter entries and reports a maximum logit difference of 0.0. The folder written by a
successful run is byte-for-byte the repository on the hub; the upload receipt is written next to it, not
inside it, so it can never enter the manifest of a later build.

The GitHub release route stays available for the raw checkpoint:

```powershell
git tag model-v1
git push origin model-v1
gh release upload model-v1 datasets/multilingual/checkpoints/model/model_best.pt --clobber
```

A verification job can then run the gates of section 7 before publishing, because
`datasets/multilingual/tools/evaluate_model.py` exits with code 1 when any gate fails and writes the per-gate `passed`
flags into its JSON report.

Everything the pipeline runs fits on a CPU runner. `datasets/multilingual/checkpoints/` stays out of
git, the access token is only ever read from the environment and never passed as an argument, and no stage
of the training or evaluation pipeline contacts an external hub or downloads a model.
